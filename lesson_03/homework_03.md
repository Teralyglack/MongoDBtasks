### Ответы на вопросы

Ответьте самостоятельно по 3–5 предложений.

1. Какие поля есть у документа товара? Какие поля должны иметь числовой тип и
   почему цену и количество нельзя хранить строками?

В Compass у товара видны такие поля:

_id: уникальный номер документа (например, "p-001");
sku: артикул ("SKU-NB-001");
title: название;
brand: производитель;
category: категория;
price: цена;
rating: рейтинг;
reviews: количество отзывов;
added: дата добавления;
specs и stock: массивы с характеристиками и остатками;
qty_total: общий остаток на складе;
free_shipping: бесплатная доставка.

Числовой тип должны иметь price, rating, reviews и qty_total.

Почему цену и количество нельзя хранить строками:

Со строкой нельзя считать. Операция $inc (прибавить 5 к остатку) работает только с числами, со строкой "12" она выдаст ошибку.
Строки сортируются по буквам, а не по величине: "9" окажется «больше» "10", и сортировка по цене сломается.
Условия «дороже» и «меньше» ($gt, $lt) тоже будут сравнивать текст, а не числа.
Суммы и средние значения по строкам посчитать нельзя.

3. Чем обычное чтение коллекции отличается от поиска по условию? Приведите
пример запроса или фрагмента кода из своей работы.
Обычное чтение возвращает все документы коллекции без отбора. Поиск по условию возвращает только те документы, которые подходят под заданное условие.
Примеры из моей работы:

python
# поиск по условию: только ноутбуки
products.find({"category": "ноутбуки"})

Вернул 5 товаров из 21.

python
# без условия: весь каталог
products.find({})

Вернул все 21 товар.

5. Как вы проверили, что операция действительно изменила данные в MongoDB, а не
   только текст в интерфейсе программы?
С этим даже возникли трудности, т.к Mongo DB и Compass слушали 2 сервера одновременно и в Compass данные не обновлялись. Но я решила эту проблему, отключив один сервер командой Stop-Service MongoDB. Я смотрела по интерфейсу Compass и обновляла базу.
